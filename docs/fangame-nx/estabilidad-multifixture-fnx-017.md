# Misión 011 · FNX-017 · estabilidad y dos fixtures con un NRO

Rama `test/fnx-017-estabilidad-multijuego`, creada desde `fix/fnx-016-sdl-shutdown` (`f2733b6`). Alcance local: ninguna operación sobre la Switch, MTP o unidades extraíbles.

## Contrato comprobado en el código

En Switch, `nxSetupWorkdir()` intenta primero el directorio de `argv[0]` (la ruta del NRO) y solo lo acepta si contiene `mkxp.json`; como segunda opción lee una única ruta fija de `romfs:/juego.txt`. Después `Config::read()` abre `mkxp.json`; `customScript` hace que `binding-mri.cpp` lea un fichero Ruby relativo al directorio activo y lo evalúe. `nx_carpeta_juego_fija()` acepta la primera carpeta y no ofrece una segunda selección en el mismo proceso. El cierre del parche `2a759c5` desasocia GL en el hilo RGSS antes de `SDL_GL_DeleteContext` y `SDL_DestroyWindow`; una prueba física M016 recorrió toda la traza y volvió al Homebrew Menu.

`fnx016-sdl-fix` conserva los registros entre arranques: `fnx009-probe.log` abre con `a` y comienza cada ejecución con `=== FNX009 INICIO ===`; `fnx009-escritura.txt` abre con `ab`; `mkxp-debug.log` usa `fopen(..., "a")`; `mkxp-boot.log` usa `O_APPEND` y abre cada proceso con `[build]`. Este último rota a `.1.log` a partir de 1 MiB. Las marcas delimitan ejecuciones por orden, pero no son un ID persistente exclusivo. Para cinco ciclos, preservar una **copia previa** de los cuatro archivos y analizar solo el sufijo añadido; si alguno cambia de prefijo o rota, detener el análisis automático y conservar ambas generaciones.

## Un NRO, dos fixtures sintéticos

El paquete local propuesto pone **un solo NRO** en `switch/fnx017-dual/` y, junto a él, `mkxp.json`, `Data/Scripts.rxdata`, `Graphics/`, `Audio/` y `lib/` para superar el preflight actual. `customScript` carga `selector.rb`, un **arnés de prueba Ruby** que lee `siguiente.txt` (`A` al inicio), ejecuta `fixtures/a/scene.rb` o `fixtures/b/scene.rb` y, solo tras una salida normal, deja preparada la otra letra para el siguiente lanzamiento. El usuario vuelve a abrir el **mismo archivo NRO** para ejecutar B. A y B tienen textos y colores distintos, `entrada.txt` propio, log de eventos propio y marcador de escritura propio. No se copian dos ejecutables ni se recompila el motor por fixture.

Esta prueba **sí** puede demostrar que el mismo ejecutable procesa dos cargas Ruby sintéticas en procesos consecutivos y que sus ficheros no se mezclan. **No** demuestra un lanzador previo al runtime, carga de dos juegos RPG Maker completos desde directorios externos ni reinicialización de Ruby/SDL dentro del mismo proceso. La selección ocurre en Ruby **después** del arranque RGSS. El contrato actual impide seleccionar dos carpetas de juego externas con un único NRO sin cambiar la entrada del motor. Para la siguiente misión se propone un adaptador mínimo previo a `Config::read` que lea una ruta seleccionada de un manifiesto controlado, la canonice y valide bajo una raíz autorizada antes de llamar a `nx_carpeta_juego_fija`. Deberá definir ID estable y destino de logs/guardados; no se implementa aquí.

El NRO del paquete se generó desde el **mismo ELF** de M016 solo para mostrar un título NACP inequívoco en Homebrew Menu; no se modificó el motor. Su cuerpo NRO de 17 719 296 bytes es idéntico, byte a byte, al NRO que funcionó en M016. El ASET contiene el icono neutro propio usado en M016, NACP nuevo y el RomFS del motor con `LEEME.txt`, sin contenido de juegos. La biblioteca `libgcc` aislada no se volvió a enlazar: el mapa de M016 referencia únicamente `src/build-logs/fnx016-isolated-prefix/pic/libgcc.a` (SHA-256 `b7bca10e…b17c5c9811c837dc`) para sus miembros `libgcc.a`; el ELF completo mantiene SHA-256 `28dea29d…afa6e421a7cae5aaa79ee57`. No se afirma una nueva compilación limpia.

## Riesgos y siguiente paso

El selector Ruby depende de que el directorio de trabajo sea el del NRO y de que `load` abra los scripts locales desde él; el código y la simulación lo respaldan, pero el nuevo paquete no se ha ensayado en hardware. Los logs `mkxp-boot.log` y `mkxp-debug.log` son compartidos por A/B dentro de esta carpeta y se correlacionan por orden con `fnx017-selector.log`; los logs de escena y marcadores de escritura sí están aislados por fixture. La escritura de `siguiente.txt` se hace al completar el script; un apagado durante esa escritura podría dejar una selección inválida, que el selector rechazaría. Antes de un lanzador real se necesitará selección de carpeta externa **previa** a RGSS, aislamiento de guardados y definición explícita del ciclo de vida del runtime. Esa es la siguiente tarea de diseño; esta misión no la implementa.

Resultado físico de cinco ciclos y de dos fixtures: **pendiente**. FNX-017 está preparado localmente, no validado en Switch. Durante esta misión no se accedió a MTP, microSD ni ninguna unidad extraíble, ni se instaló o retiró archivo alguno en la consola.
